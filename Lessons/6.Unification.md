# Lesson 6: Unification - The Heart of Prolog

This is an important lesson. **Unification** is the core mechanism that makes Prolog work. It's how Prolog matches patterns and finds answers.

---

## 🎯 What Is Unification?

**Unification** is the process of matching two things to see if they can be the same.

**Simple analogy:** Imagine two puzzle pieces. Can they fit together? If yes, they unify. If no, they don't.

**In Prolog:** 
- Can these two expressions be made identical by assigning values to variables?
- If yes, they unify and we learn what the variables must be.
- If no, unification fails.

---

## 🧩 Concrete Examples of Unification

### Example 1: Simple Matching

**Query:** `?- parent(tom, bob).`

**Unification process:**
- Compare: `parent(tom, bob)` (from query)
- With: `parent(tom, bob)` (fact in database)
- Can they be identical? YES! They already are.
- Result: **Unifies successfully** → Answer: `true`

### Example 2: Using a Variable

**Query:** `?- parent(tom, X).`

**Unification process:**
- Compare: `parent(tom, X)` (from query, X is unknown)
- With: `parent(tom, bob)` (fact in database)
- Can they be identical? YES! If X = bob
- Unification assigns: X = bob
- Result: **Unifies successfully** → Answer: `X = bob`

### Example 3: Failing to Unify

**Query:** `?- parent(tom, alice).`

**Unification process:**
- Compare: `parent(tom, alice)` (from query)
- With: facts like `parent(tom, bob)`, `parent(tom, liz)`, etc.
- Can `alice` match `bob`? NO
- Can `alice` match `liz`? NO
- Can `alice` match any of the stored values? NO
- Result: **Unification fails** → Answer: `false`

### Example 4: Variables on Both Sides

**Query:** `?- parent(X, Y).`

**Unification process:**
- Compare: `parent(X, Y)` (both variables)
- With: `parent(tom, bob)` (first fact)
- Can they be identical? YES! If X = tom AND Y = bob
- Unification assigns: X = tom, Y = bob
- Result: **Unifies successfully** → Answer: `X = tom, Y = bob`

## 🔍 Detailed Unification Rules

**Two things unify if they are:**

### Rule 1: Identical Constants
```prolog
tom unifies with tom ✓
bob unifies with bob ✓
tom unifies with bob ✗
```

### Rule 2: A Variable Unifies with Anything
```prolog
X unifies with tom       → X = tom
X unifies with bob       → X = bob
X unifies with anything  ✓
```

### Rule 3: Same Structure with Matching Arguments
```prolog
parent(tom, bob) unifies with parent(tom, bob)  ✓
parent(tom, bob) unifies with parent(tom, X)    ✓ (X = bob)
parent(tom, bob) unifies with parent(X, Y)      ✓ (X = tom, Y = bob)
parent(tom, bob) unifies with parent(bob, tom)  ✗ (wrong order)
parent(tom, bob) unifies with teacher(tom, bob) ✗ (different names)
```

### Rule 4: A Variable Can Only Have One Value (in a query)
```prolog
parent(X, X)  unifies with parent(tom, tom)   ✓ (X = tom for both)
parent(X, X)  unifies with parent(tom, bob)   ✗ (X can't be both tom and bob)
```

## 🎬 Let's Trace Through Real Queries

### Trace 1: Simple Query

**Query:** `?- parent(bob, ann).`

**Step 1:** Try to unify with each fact:
```
parent(bob, ann) unifies with parent(tom, bob)?  NO
parent(bob, ann) unifies with parent(tom, liz)?  NO
parent(bob, ann) unifies with parent(bob, ann)?  YES! ✓
```

**Result:** `true.`

### Trace 2: Query with Variable

**Query:** `?- parent(tom, X).`

**Step 1:** Try to unify with each fact:
```
parent(tom, X) unifies with parent(tom, bob)?  
  - "tom" matches "tom" ✓
  - X matches bob ✓
  - YES! Set X = bob

parent(tom, X) unifies with parent(tom, liz)?
  - "tom" matches "tom" ✓
  - X matches liz ✓
  - YES! Set X = liz

... (continue for other facts)
```

**Result:** 
```
X = bob ;
X = liz
```

### Trace 3: Rule with Unification

**Query:** `?- grandparent(tom, ann).`

**Step 1:** Look for `grandparent` facts: None found

**Step 2:** Look for `grandparent` rules:
```prolog
grandparent(X, Z) :- parent(X, Y), parent(Y, Z).
```

**Step 3:** Try to unify query with rule head:
```
grandparent(tom, ann) unifies with grandparent(X, Z)?
  - tom matches X  → X = tom
  - ann matches Z  → Z = ann
  - YES! ✓
```

**Step 4:** Now prove the rule body with X=tom, Z=ann:
```
parent(tom, Y), parent(Y, ann)
```

**Step 5:** Find Y:
```
parent(tom, Y): Can find Y = bob or Y = liz

If Y = bob:
  parent(bob, ann)? YES! ✓
  All conditions satisfied! 
  Answer: true
```

## 🧩 Compound Unification

Variables can appear in complex structures.

### Example 1: Matching Lists (we'll learn lists in detail later)

```prolog
[H|T] unifies with [1,2,3]?
  - H (head) matches 1     → H = 1
  - T (tail) matches [2,3] → T = [2,3]
  - YES! ✓
```

### Example 2: Matching Nested Structures

```prolog
person(name(john), age(25)) unifies with person(name(N), age(A))?
  - name(N) matches name(john)  → N = john
  - age(A) matches age(25)      → A = 25
  - YES! ✓
```

---

## 🚨 The Golden Rule: Variables Must Unify Consistently

Once a variable gets a value, it **keeps that value** throughout the query.

### Example: Consistent Variable Values

**Query:** `?- parent(X, Y), parent(X, Z).`

**What this means:** "Find X such that X is a parent of both Y and Z"

**Unification:**
```
First parent(X, Y):
  X = tom, Y = bob ✓

Second parent(X, Z) with X = tom (MUST stay tom!):
  parent(tom, Z): Z can be bob or liz
  
If Z = bob: Both conditions satisfied! (X=tom, Y=bob, Z=bob)
If Z = liz: Both conditions satisfied! (X=tom, Y=bob, Z=liz)
```

**Result:** 
```
X = tom, Y = bob, Z = bob ;
X = tom, Y = bob, Z = liz ;
X = tom, Y = liz, Z = bob ;
X = tom, Y = liz, Z = liz ;
```

**Key Point:** Once X = tom in the first goal, it STAYS tom in the second goal. This is what makes Prolog's reasoning powerful!

## 🎯 Real-World Unification Analogy

Imagine you're trying to fit keys into locks:

- **Fact:** A specific key-lock pair that's already cut
- **Query:** A pattern of what you're looking for
- **Unification:** Testing if the key and lock match

```
Query: I'm looking for a key that fits a lock called "parent(tom, ?)"

Fact 1: parent(tom, bob)    → Does it fit? YES! bob is the answer
Fact 2: parent(tom, liz)    → Does it fit? YES! liz is another answer
Fact 3: parent(bob, ann)    → Does it fit? NO! tom doesn't match bob
```

## 🔍 Unification in Rules

Here's where it gets interesting. When you use rules, unification happens multiple times:

**Rule:** 
```prolog
grandparent(X, Z) :- parent(X, Y), parent(Y, Z).
```

**Query:** `?- grandparent(tom, ann).`

**Unification steps:**
```
1. Unify query with rule head:
   grandparent(tom, ann) unifies with grandparent(X, Z)
   Result: X=tom, Z=ann

2. Unify first goal:
   parent(tom, Y) unifies with parent(tom, bob)
   Result: Y=bob

3. Unify second goal (using Y=bob):
   parent(bob, ann) unifies with parent(bob, ann)
   Result: SUCCESS!

4. Return: true (all unifications successful)
```

If step 3 failed (no parent(bob, ann)), Prolog would backtrack and try Y=liz.

## 💡 Summary

Unification is:
- **Matching patterns** to facts and rules
- **Assigning values** to variables
- **Checking if** two things can be identical
- **The mechanism** that makes Prolog work

When you write `?- parent(tom, X).`, Prolog:
1. Looks at each fact
2. Tries to unify the query with that fact
3. When unification succeeds, assigns values to X
4. Returns those assignments as answers

This simple unification mechanism is the foundation of Prolog's power! 🚀
